## Runtime evidence boundary

- #92 covered active scan, add/up/down/delete loops, and rmmod with/without a virtual interface. #93 covered AP reconnects, AP start/stop, and idle/traffic/hostapd-stopped rmmod. Lockdep stayed enabled and clean.
- STA association never succeeded. Join-success, join-timeout, wrong-key, roaming, P2P, TDLS, mesh, MP, DFS, and explicit IPS transitions are not claimed as covered.

## 020 implementation addendum

- `rtw_joinbss_event_prehandle:2259` remains the confirmed same-instance cycle: the cancel point holds `pmlmepriv->lock`, and `rtw_join_timeout_handler:3012` acquires the same lock.
- Implemented 020 keeps that softirq-capable point non-synchronous. Process-context drains use `_enter_critical_mutex_lock()` because `_enter_critical_mutex()` is interruptible and its result is normally ignored.
- The DRAINING owner is exclusive: cancel cannot change DRAINING/SHUTDOWN to IDLE; during DRAINING it may only discard a deferred arm. This prevents an old drain from deleting a newly armed join timeout.
- `rtw_cancel_all_timer()` has four direct caller families: virtual-interface stop, device unload, MI suspend cancellation, and silent reset. Their two-level chains are process/PM/command-worker context; none is a timer/tasklet caller.
- An explicit initialization flag is required because virtual adapters copy the primary `_adapter`, and primary probe failure does not call `rtw_free_drv_sw()`. Implemented 020 clears copied state, deinitializes on `rtw_init_drv_sw()` failure, rejects duplicate timer initialization, and makes final assoc timer destruction sequentially idempotent.
- `shutdown` closes the timer but does not destroy `drain_mutex`; destruction is deferred to final `deinit`, after driver threads and restartable drains have stopped. The callback tree never takes `drain_mutex` or calls drain/shutdown/deinit.
- The classifications below remain evidence for the unmodified patch-019 tree. Implemented 020 must still pass the revised L3 timeout, reconnect, adapter-reuse and AP-regression tests before any row gains runtime coverage.

## Limits

The call graph is textual. Caller-side tracing stops after two reverse levels; callback-side tracing includes the callback plus two callee levels. Function pointers, macros, aliases, conditional compilation and runtime object identity can evade it. An unresolved chain stays UNTESTED. Lockdep on the exact executed path is the acceptance authority.
